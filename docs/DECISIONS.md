# Decisions

Append new decisions at the bottom. Don't rewrite old entries; supersede them with a new one.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-11-05 | Custom engine on wgpu/winit/egui, not Bevy or Godot | Full control over a small, specialized engine; grow it only as needed |
| 2026-11-05 | Acoustics via Steam Audio through AudioNimbus | Real-time occlusion, reflections, reverb and HRTF with a safe Rust API; pyroomacoustics is offline/Python and only useful as inspiration |
| 2026-11-05 | Own in-engine 3D editor, not Blender-as-editor (Skein) | Wanted a real visual editor; Blender stays for modelling |
| 2026-11-05 | One binary; the editor is the game with a UI on top | No export step, no editor/game mismatch, Play/Stop in place |
| 2026-11-05 | Inspector generated from `bevy_reflect` components | Adding a behavior = writing one struct; keeps the editor maintenance-free |
| 2026-11-05 | Undo/redo via commands from the first editor milestone | Retrofitting undo later means rewriting every tool |
| 2026-11-05 | Scenes in RON, models in glTF | Plain-text, git-diffable scenes; standard model format |
| 2026-11-05 | Crisp HD output with an integer render-scale factor (default internal height ~540–720 lines), nearest-neighbor upscale | Looks HD with a subtle pixel texture; saves 4–9× lighting compute versus native, spent on lighting and fog |
| 2026-11-05 | Lighting = baked path-traced GI + volumetric fog + real-time shadows + post-processing; live ray-traced effects only where they earn it | Atmospheric lighting at 60+ fps; no RTX hardware needed |
| 2026-11-05 | Retro effects (vertex snapping, affine warping, dithering) are optional toggles, off by default | The look comes from low-poly geometry, crisp low-res textures and lighting, not from emulating old hardware |
| 2026-11-05 | Load the whole world at once, but every object belongs to a zone | Low-poly worlds fit in memory; zones enable culling, sim radius, probes, map later |
| 2026-11-05 | Minimal amber terminal-style UI for the editor and default game UI | Desired aesthetic (Blade Runner / Evangelion, but sparser) |
| 2026-11-05 | First milestone is an audio grey-box test | Simulated acoustics are the riskiest and most important feature; prove them before anything else |
| 2026-11-05 | Engine repo is open source and generic; games are separate content-only projects outside this repo, loaded with `--game` | Game content can stay private; keeps game-specific logic out of the engine |
| 2026-11-05 | `sandbox/` test project inside the engine repo, default `--game` | A public place to test engine features |
| 2026-11-05 | No mention of any specific game anywhere in this repo | The engine is a standalone open-source product |
| 2026-11-05 | Supersedes "first milestone is an audio grey-box test": order is renderer → first-person controller + test level → editor → Play/Stop → behaviors → audio | User wants a playable, tunable first-person character in a 3D test level first; audio is tested later inside the 3D engine instead of a throwaway prototype |
| 2026-11-05 | First-person character controller; third-person only if a game needs it | User's choice for the first character |
| 2026-11-05 | Physics with rapier3d | Standard Rust physics crate; provides colliders, a kinematic character controller (steps, slopes, ground snapping) and rigid bodies for PhysicsBody |
| 2026-11-05 | Movement properties in the game project's `player.ron`, tunable live in-game (F1) with save and hot reload | Feel is game-specific data and is tuned by playing, not recompiling |
| 2026-11-05 | Extra crates: `glam` (math), `bytemuck` (GPU buffer casts), `pollster` (block on wgpu's async setup), `log` + `env_logger` (logging), `thiserror` / `anyhow` (errors) | Small, standard companions to wgpu; glam is the common choice around wgpu and is re-exported from `engine` so games share one math type |
| 2026-11-05 | Tone mapping is AgX (polynomial fit), applied in the upscale pass | Handles saturated highlights more gracefully than ACES, suits a moody, low-saturation look |
| 2026-11-05 | Default render-scale factor = ceil(output height / 720) | Matches the brief's table (1080p → 2, 1440p → 2, 4K → 3); manual override 1–8, letterbox for leftover pixels |
| 2026-11-05 | Scene renders to an Rgba16Float target; the window surface is non-sRGB and the upscale shader writes display-encoded values | Keeps HDR until tone mapping; egui also prefers a non-sRGB surface, so both share one target |
| 2026-11-05 | Point-sampled textures still get mipmaps, blended linearly between levels | Crisp texels up close without distant grid lines shimmering |
| 2026-11-05 | Milestone 1's test scene is hard-coded in `crates/app/src/demo.rs` | No scene format until milestone 3; it moves into `sandbox/scenes/` then |
| 2026-11-05 | Engine pins `glam` to the version rapier3d uses (0.33) | rapier 0.36 is glam-based; one `Vec3` type across rendering and physics, no conversions |
| 2026-11-05 | `serde` for (de)serializing RON files | Standard companion to `ron` |
| 2026-11-05 | `player.ron` hot reload polls the file's modified time (every 250 ms) instead of using a file-watcher crate | One file, no new dependency; switch to `notify` when many files need watching |
| 2026-11-05 | Player settings have neutral fallback defaults in engine code; the game's `player.ron` holds the real tuning | A missing or partial file still works and "Reset to defaults" has something to reset to; games never depend on engine constants |
| 2026-11-05 | rapier's `KinematicCharacterController` does collision (slide, autostep, slopes, ground snap); the engine computes the desired motion | Reuses well-tested collide-and-slide; acceleration, jump and camera feel stay ours and data-driven |
| 2026-11-05 | Vertical motion integrates with v·dt + ½·a·dt² per frame, no fixed timestep yet | Exact for constant gravity, so jump height is frame-rate independent (tested at 30–500 fps); add a fixed step when dynamic physics arrives |
| 2026-11-05 | Milestone 2's test level is built in code in `crates/app/src/test_level.rs` | Allowed by the roadmap; moves to a scene file in milestone 3 |
| 2026-11-05 | Supersedes the rapier-collision controller entry: the player is a floating capsule (starts `step_height` above the feet) plus a downward ground probe (small sphere cast, center ray for the walkability normal); rapier's controller is only used to slide the capsule along walls | rapier's autostep failed on capsule-vs-step-edge contacts, and feeding small downward moves into its skin gap sank the player at some frame rates (144 fps); the probe gives smooth stairs and slopes at full speed, tested at 30–2000 fps |
| 2026-11-05 | Horizontal velocity follows the capsule's actual displacement (wall clipping) | Safe now that the floating capsule never touches the ground: any shortfall comes from a wall |
| 2026-11-05 | Scene data model: plain Rust (a scene is a list of objects, each with transform, zone and a list of reflected components); no ECS library for now | Simple and debuggable; enough for the object counts we expect. Revisit if behaviors or performance need an ECS |
| 2026-11-05 | Scene components are variants of one `Component` enum (serde, RON) | Readable, typed RON with no type registry; adding a component = its struct + one enum variant. Revisit if reflection-based serialization becomes simpler once `bevy_reflect` is in |
| 2026-11-05 | Transform rotation is stored as Euler degrees (applied Y, X, Z), not a quaternion | Readable and hand-editable in RON and the inspector |
| 2026-11-05 | Objects reference their zone by name; loading fails on an unknown zone | Every object must belong to a zone, enforced from the first scene file |
| 2026-11-05 | `game.ron` holds the game name and start scene path | The engine needs an entry point into a project; more settings (musical key etc.) are added when needed |
| 2026-11-05 | `PlayerStart` component added in milestone 3 (ahead of milestone 4) | Needed so the test level is pure data, with no spawn point left in code |
| 2026-11-05 | The editor is a module of the `engine` crate, not the `app` crate | It needs the runtime's internals (renderer viewport, input, scene); the app stays a thin binary. Split into its own crate if it grows large |
| 2026-11-05 | Editor viewport = the space between the panels; the scene renders (and render-scales) into just that rect | The 3D view is never covered by UI, and the pixel grid stays exact |
| 2026-11-05 | Editor camera moves only while the right mouse button is held | Keeps letter keys free for editor shortcuts (gizmo modes etc.) |
| 2026-11-05 | Click-to-select raycasts rapier's collider BVH (collider `user_data` = object index) instead of a separate render-side BVH | Reuses the acceleration structure we already have; objects without a collider (e.g. PlayerStart) get picked via icons later |
| 2026-11-05 | `bevy_reflect` 0.20 (standalone, `glam` feature) for the generated inspector | In the brief; it uses the same glam 0.33 as rapier and the engine, so `Vec3` fields reflect directly |
| 2026-11-05 | Undo commands snapshot the whole object (`SetObject { before, after }`) | One command type covers every inspector and gizmo edit; objects are small. Add finer commands (add/delete/reorder) as features need them |
| 2026-11-05 | Edits apply live but are recorded as one undo step when the drag or text entry ends | A whole drag is one Ctrl+Z, as in other editors |
| 2026-11-05 | Changing an enum's variant in the inspector (e.g. Box → Cylinder) is not supported yet | Needs default values per variant; add when it's missed |
| 2026-11-05 | Gizmo uses the core `transform-gizmo` crate, drawn with our egui, instead of `transform-gizmo-egui` | The egui integration (0.11) targets egui 0.36; the core crate is renderer-agnostic, so we feed it our matrices and paint its triangles |
| 2026-11-05 | Gizmo modes on W/E/R (Unity style), only while not flying; global orientation | Handles stay visible and discoverable; Blender-style G/R/S can be added later |
| 2026-11-05 | Holding Ctrl while dragging snaps: 0.25 m (the grid's fine lines), 15°, scale 0.1; Shift stays egui's fine control | Requested by the user: blocky, grid-aligned placement as the opposite of Shift |
| 2026-11-05 | `gltf` crate for model loading | The standard Rust glTF reader; its default `import` feature also decodes images, which textures will need later |
| 2026-11-05 | Models: a `Model { path, color }` component; meshes cached per path; flat color for now (no textures yet); a static triangle-mesh collider; a 0.5 m placeholder box if the file can't be loaded | Smallest useful model support; a bad path never hides the object or crashes |
| 2026-11-05 | Unsaved-changes tracking uses undo-step ids, and switching scenes or closing with changes asks Save / Discard / Cancel | Exact even after undo/redo; never lose work silently |
| 2026-11-05 | Sandbox `models/arch.gltf` is generated by us (a script, not committed) | Publishable test content with no license questions |
| 2026-11-05 | New milestone 4 "Creating objects" inserted after the editor loop; former milestones 4–10 are now 5–11 (entries above use the old numbers) | Adding, deleting and reshaping objects, model drag and drop, and model textures were missing from the editor loop and are needed before building levels |
| 2026-11-05 | Two ways to create objects: drag in model files (glTF, preferably `.glb`, copied into the project's `models/`), and primitives created in the editor whose shape type can be changed later | Blender stays the modelling tool; quick grey-boxing happens in the editor. `.glb` is one self-contained file, so nothing gets lost when copying |
| 2026-11-05 | Add/delete/duplicate are `Edit::Add` / `Edit::Remove` (whole-object snapshots at an index); edits report a `Change` (modified / added / removed index) so selection follows shifted indices, and add/remove rebuild all draws | Keeps one simple undo model; rebuilding draws is cheap at our object counts |
| 2026-11-05 | New primitives rest on the surface the camera looks at (up to 20 m), snapped to the 0.25 m grid along the surface; otherwise they float 4 m ahead. Duplicates go in place, right after the original, and become the selection | A fixed distance put objects inside walls; in-place duplicates (as in Unity) are moved with the gizmo |
| 2026-11-05 | Supersedes "changing an enum's variant is not supported": primitives get a TYPE picker in the inspector; the new shape fills about the same bounding box (a plane gains 1 m of height), round shapes keep their segment count | Requested in milestone 4; one explicit conversion per shape instead of generic enum defaults |
| 2026-11-05 | Stairs become a primitive (milestone 12, after the current milestones): inspector fields for width, height, step count and step depth, and curving via a turn angle plus inner radius. A freeform path (draggable curve points) is deferred | Parametric curving covers straight, curved and spiral stairs at the cost of one primitive; a path tool is milestone-sized and only worth it if missed |
| 2026-11-05 | Collision toggle per object, as milestone 4.1 (right after milestone 4): turning it off keeps a collider for click-to-select but in a group the player ignores | The per-frame gain from removing distant static colliders is small (rapier only checks nearby ones); the real wins are walk-through decoration and faster collision rebuilds, and selection must keep working |
| 2026-11-05 | `windows-sys` 0.52 (Windows only, the version winit already uses) for one `GetCursorPos` call in `cursor.rs` | winit 0.30 drops the position of a file drop and sends no cursor events during the drag, so the drop point has to be asked from the OS |
| 2026-11-05 | Dropped models are copied into `models/` and never overwrite: an identical file is reused, a different one with the same name gets `-2`, `-3`...; a `.gltf` brings its relative buffer and image files and refuses if one would clash; a file already inside the project is used in place. The model rests on the surface under the cursor (its bounding box touches it, so a Blender origin at the base lands on the floor) | No silent changes to models other objects use (re-exporting over a file is hot reload's job); never a half-copied `.gltf` |
| 2026-11-05 | Model materials: each glTF material becomes one image (base color texture × base color factor, baked on load; untextured = one texel of the factor), and a model draws one part per primitive with its own texture bind group. Primitives bind the grid through the same slot. Mips only for square power-of-two textures; alpha is ignored for now | One texture path in the shader; Blender material colors show up too, not just textures; transparency and alpha cutout come when a game needs them |
| 2026-11-05 | Model hot reload polls each loaded model's modified time on the same 250 ms tick as `player.ron` (still no `notify`); a model reloads once its time changed and then held for one poll, and everything is redrawn and re-collided | A handful of `metadata` calls per tick is negligible; waiting one poll avoids reading a file an exporter is still writing |
| 2026-11-05 | Play/Stop in the editor: F5 or the top-bar button. Play snapshots the scene and the editor camera, spawns the player at the PlayerStart with `player.ron`, and locks editing (panels disabled, gizmo hidden, no imports); the game's own keys apply (Esc frees the mouse, click captures it, R, F1, F2). Stop restores the snapshot and camera; closing while playing stops first | Edits made while playing would be lost on Stop, so they are blocked rather than silently discarded; F5 is the common "run" key |
| 2026-11-05 | The PlayerStart is drawn as an overlay marker (post, facing arrow, START label) and selected by clicking it, not as render geometry with a collider; ADD → PLAYER START places one on the aimed surface facing the camera's way (15° steps), only if the scene has none | Editor-only and never in the game or physics; one start per scene since play uses the first |
| 2026-11-05 | Behaviors run in `behaviors.rs` while the game runs (play mode, or after Play in the editor; Stop drops them with the snapshot). Moving objects are redrawn per frame and their colliders moved (each collider keeps its pose relative to its object), then one physics step updates the broad phase | No ECS yet: a small per-frame pass over the objects that have behaviors. The inspector gets REMOVE per component and ADD COMPONENT (one of each kind) |
| 2026-11-05 | SoundSource, Singer and AcousticMaterial move from milestone 6 to milestone 7 (audio) | They do nothing until audio exists, so they can only be built and tested there |
| 2026-11-05 | Object references (`ObjectRef`) are object names, picked from a dropdown in the inspector; a name that no longer exists shows as MISSING and does nothing | Readable in RON like zone names; renaming a target doesn't update references yet (add when it's missed) |
| 2026-11-05 | Door = slide offset + swing angle around a hinge point (both in the door's own axes), eased over `duration`; Switch = press E within 2.5 m while looking at it, or `pressure_plate` (toggles while stood on, back when left); a switch toggles its target door | No enums in components yet (the inspector can't switch variants), so plain fields cover sliding, swinging and both |
| 2026-11-05 | PhysicsBody: dynamic rapier bodies only while the game runs (editor stays static); fixed 1/60 s steps with up to 0.1 s catch-up; models become convex hulls when dynamic; the player pushes bodies by setting their velocity toward its own speed, scaled down by mass (about 80 kg player) | Supersedes the earlier "no fixed timestep yet": dynamic physics needs one. The kinematic controller can't apply forces, so pushing is done explicitly |
| 2026-11-05 | Audio crates: `audionimbus` 0.16 (`auto-install`), `cpal` 0.18 for the output device, `hound` to read WAV files | AudioNimbus/Steam Audio is in the brief; cpal is the standard Rust audio output; hound is the small standard WAV reader |
| 2026-11-05 | Building needs LLVM (libclang + the `clang` executable on PATH: AudioNimbus runs bindgen, which finds C headers through `clang`); installed with `winget install LLVM.LLVM` | Without `clang` on PATH bindgen fails with "stddef.h not found", even when libclang itself is found |
| 2026-11-05 | Audio design: the listener is the active camera (so the editor previews sound); the main thread runs Steam Audio's simulation each frame and passes per-voice parameters to the mixer on the cpal callback thread through a `try_lock` (never blocking); new voice sets go over a channel; master limiter (instant attack, 0.25 s release, ceiling about -1 dBFS); a SoundSource without a clip plays a generated plucked-string phrase | Simple and real-time safe enough for now; reflections will move to their own thread (milestone 7 later step) |
| 2026-11-05 | Singer moves out of milestone 7 to an optional "Later" section | The user will mostly use their own recorded tracks (SoundSource); Singer needs the music system and voices, which are undecided |
| 2026-11-05 | Acoustic geometry: solid objects (collision on) go to Steam Audio; static ones merged into one mesh, rebuilt when a fingerprint of the static geometry changes (checked every 0.25 s); objects with Door/Floating/PhysicsBody are instanced meshes whose transforms follow every frame. Occlusion is volumetric (source = 0.4 m sphere, 16 samples) with transmission through up to 3 surfaces | Walk-through decoration shouldn't block sound; instancing keeps opening doors and moving props cheap |
| 2026-11-05 | AcousticMaterial = one `preset` (Generic, Wood, Stone, Marble, Brick, Concrete, Plaster, Carpet, Velvet, Glass, Metal, Water, Gravel) using Steam Audio's published values (marble, velvet, water ours); objects without one are Generic. The inspector now shows enums with plain variants as a dropdown | Presets are what level building needs; custom absorption values can be added when a game misses them |
| 2026-11-05 | Reflections and reverb: Steam Audio convolution reflections (first-order ambisonics, up to 3 s tails) simulated on a background thread through AudioNimbus' `wiring` (paused while nothing plays); every voice's reflections are summed into one ambisonic bus that is decoded once (binaural, or panning with HRTF off). Direct sound stays on the main thread and uses the direct-only `_subset` calls, so it never waits for a reflection pass | Full simulator calls lock both simulations and dropped the frame rate to 41 fps; the reflection thread uses about one core while sound plays (throttle when profiling says so) |
| 2026-11-05 | A/B toggles on F6–F9 (occlusion, reflections, HRTF, air absorption) with an on-screen panel; while the game runs Q claps at the listener, M moves the first looping sound source to just in front of the player, and footsteps play every 0.75 m walked (and on landing) with the floor's AcousticMaterial. Claps and footsteps are generated unless the project has `audio/clap.wav` / `audio/footsteps/<material>.wav`; they play from a pool of 6 one-shot voices that keep simulating until their reverb tail is over | Test tools the roadmap asks for, kept generic: any game gets footsteps per material for free and can replace the sounds with recordings |
| 2026-11-05 | Objects carrying a SoundSource are left out of the acoustic geometry | Otherwise a sound on a solid object (a ball, a radio) is muffled by its own shape |
| 2026-11-05 | `sandbox/scenes/acoustics.ron`: open gravel field → small wooden room (velvet ceiling, dry) → narrow stone corridor → door with switch → 16×16×10 m marble hall with the looping source | Milestone 7's four-space test scene |
| 2026-11-05 | Supersedes the physical transmission values: transmission is tuned for games (through a whole solid object: wood about 30/15/6 % low/mid/high, glass 35/20/8, velvet 50/30/15, stone and marble about 5/2/1) and converted to per-face values as t^(2/3), because Steam Audio combines a solid's two faces as t^1.5 (measured) | User testing: with Steam Audio's physical values a closed wooden door silenced the sound completely; occlusion should muffle, not mute |
| 2026-11-05 | The player's own sounds (claps, footsteps) are never occluded; footsteps play 15 cm above the floor; 10 one-shot voices | Footsteps on the floor surface were half "inside" the floor for volumetric occlusion and came out muffled or missing |
| 2026-11-05 | Footsteps follow the head bob: one bob cycle is one step and the foot lands at the bob's lowest point; the tuning panel's "BOB STRIDE" is now "STEP LENGTH" (still `bob_stride` in `player.ron`) | One setting tunes both, and steps stop when the bob stops; the user couldn't find the bob speed under its old name |
| 2026-11-05 | Supersedes the single-simulator setup: direct sound and reflections use separate simulators, each with its own copy of the acoustic scene; the direct one commits moving doors on the main thread at once, the reflection one between passes. SoundSource gets `radius` (default 1 m) for volumetric occlusion, 32 occlusion samples, and occlusion/transmission are smoothed over 0.1 s | With one shared scene a door's movement only reached occlusion after a reflection pass, so the volume jumped when the door was already open; a bigger source sphere makes partly open doors let sound in gradually |
| 2026-11-05 | Mixer frame 512 samples and a matching device buffer when the device allows (else its default) | Lower latency: footsteps and claps were noticeably late |
| 2026-11-05 | A reflection source follows the listener (the reverb of the listener's room). The player's own sounds use it instead of their own pooled sources, and the part of a scene sound that comes through walls ((1 - occlusion) × transmission) is fed into it | Pooled voices briefly used the reverb of wherever they last played; and Steam Audio reflections never pass through walls, so closing a door cut the hall's reverb off at once. Sound through a door ringing in the listener's room is also what happens in reality |
| 2026-11-05 | New reflection results crossfade in over 0.2 s: every reverb path has two convolution effects, the latest result plays on one while the previous fades out on the other; a newer result waits until the fade is done | Each reflection pass traces random rays, so results differ slightly; switching instantly made the reverb jump. Costs memory (two 3 s convolution effects per path; the app uses about 550 MB with the test scene), to trim when profiling |
| 2026-11-05 | Zone extent = `ZoneVolume` components (a box centered on the object, turned and scaled with it); a zone may have several; where volumes overlap, the smallest wins; outside every volume the current zone stays the last one. A scene without volumes has no current zone (everything counts as active) | Chosen by the user over boxes derived from object bounds or the floor under the player: explicit, works for the fly camera, and gives reverb probes a volume to fill. Being objects, volumes get the gizmo, undo and saving for free |
| 2026-11-05 | Zone connections = `Portal { to }` components on an object in the doorway; zones sharing a portal are neighbours both ways | Chosen by the user over a list of zone pairs: a portal has a position for later portal culling and sound paths |
| 2026-11-05 | Zones can be added, renamed (objects and portals follow) and deleted when empty from the hierarchy; these edits are one undo step that snapshots the whole scene (`Edit::SetScene`) | Rare edits that touch many objects; a whole-scene snapshot is simplest and exact |
| 2026-11-05 | Looping sounds outside the current and neighbouring zones aren't simulated and fade to silence, keeping their place in the clip | Chosen by the user: cheapest, and never wrongly audible through walls |
| 2026-11-05 | Frustum culling on the CPU: each draw has a bounding sphere (mesh bounds, scaled by the object's largest axis), tested against the six planes of the view-projection each frame | A few hundred sphere tests are nothing; no GPU culling until profiling asks for it |
| 2026-11-05 | Simulation radius = the camera's current zone plus its portal neighbours. Outside it: behaviors pause (each moving object keeps its own clock, so it resumes where it stopped; switches still flip far doors, which move once active), dynamic bodies are disabled in rapier (frozen, velocity kept), looping sounds fade out over 1 s and then leave both Steam Audio simulators while their clip keeps playing silently | Follows the brief ("behaviors, physics and NPCs only update in the current and neighbouring zones"); a scene without volumes runs everything, so existing scenes behave as before |
| 2026-11-05 | Per-zone reverb probes: BAKE ACOUSTICS in the editor places Steam Audio probes on the floors inside each zone's volumes (`probe_spacing`, default 2 m, and `probe_height`, default 1.5 m, on `ZoneVolume`; the grid is centred, not started at a wall) and bakes listener-centric reverb (convolution, order 1, 3 s) on a background thread. One probe batch per zone, saved next to the scene as `<scene>.reverb` (own little-endian format: signature, then per zone name, probe positions, serialized batch) | Probe settings are data on the volume, so big open spaces can use a coarser grid; the bake belongs to the scene file and ships with the game |
| 2026-11-05 | Baked reverb is used only for the listener's room reverb (player sounds, sound through walls) when the listener's zone has a bake; scene sounds keep live reflections; F10 switches baked/live for A/B. The editor shows probe dots and NOT BAKED / BAKED / BAKE OUTDATED (a hash of the solid geometry, materials and volumes) | Brief: baked reverb for static spaces, live simulation for nearby, moving sources. An outdated bake is still used (close enough) but flagged |
| 2026-11-05 | Lighting model: the direct light of the sun and every `LightSource` is real time (shadow maps), and the bake (milestone 9, later step) holds only what can't be real time: bounce light, sky light and light from emissive surfaces. `baked` on a light means its bounce goes into the lightmap; live lights (moving, switched) get no bounce | Moving objects and flickering lanterns are lit and shadowed exactly like static ones, lights can flicker, and shadows stay crisp at our low resolution. Costs a shadow map per light, which is cached (see below) |
| 2026-11-05 | `LightSource` (color, intensity at 1 m with inverse-square falloff windowed to zero at `range`, flicker, shadows, baked); up to 32 lights shaded (nearest to the camera), the nearest 8 with shadows on get cube shadow maps (6 × 512² faces stored as 2D array layers and sampled with the same matrices they were rendered with, so no cube-map orientation convention). A light's maps are only re-rendered when it or something in its range moves; its own object never shadows it | Low-poly scenes have few lights; caching makes static lights free after the first frame |
| 2026-11-05 | Sun shadows: one 2048² orthographic map covering `shadow_distance` (default 40 m) around the camera, snapped to whole texels, 3×3 hardware-filtered PCF, fading out at the edge | Simplest map that gives window light patches crisp edges; cascades only if large outdoor scenes need them |
| 2026-11-05 | `emissive` (linear RGB, above 1 for glow) on Primitive and Model, added after lighting; it feeds bloom now and the bake and fog later | One field covers lanterns, candles and glowing water |
| 2026-11-05 | Post: bloom (5-level downsample/upsample chain from the internal HDR image, mixed in at `environment.bloom`), exposure, AgX, then color grading through a 32³ LUT per zone (`Zone.grade`: exposure, contrast, saturation, tint and an optional `.cube` file; zones without one use `environment.grade`), blended over 1.5 s when the camera changes zone, then film grain per internal pixel (`environment.grain`) | LUTs let any grading tool's output be used; a generated LUT keeps simple tweaks in RON |
| 2026-11-05 | `--scene <path>` runs a scene other than the project's start scene; `sandbox/scenes/hall.ron` is the lighting test (a dark hall with one window and one lantern) | Lighting needs its own test scene without changing the sandbox's start scene |
